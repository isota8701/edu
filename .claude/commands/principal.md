피드백을 교육학 원칙으로 증류해 과목 에이전트·커리큘럼·프로파일·결정로그에 일괄 반영하는 "원장(메타 레이어)".

## 역할 (한 줄)
`/done`이 "무슨 일이 있었나"를 기록한다면, `/principal`은 그 피드백을 **지속 가능한 교육학 원칙**으로 끌어올려 ① 과목 에이전트 정의 ② 커리큘럼 ③ 학생 프로파일 ④ `PROGRESS.md` 결정 로그에 **일관되게 전파**한다. 일종의 "학원 원장 + 교육학 전문가".

## 사용법
```
/principal 수학 — 두 자리 뺄셈을 십 만들기로 풀게 했더니 60-26이 남아 안 쉬워짐. 의도를 모르겠다
/principal 영어 — 발음은 하는데 쓰라고 하면 b/d/g/t를 헷갈림
/principal 수학 — (학원 수업자료/학교 시험 결과 첨부·요약)
/principal                # 인수 없으면 principal-log.md 미검토 대기열을 모아 처리
/principal review         # 주기 점검 — 최근 진행을 훑어 조정할 원칙이 있는지 검토
```

## 무엇이 "원칙급 신호"인가
`outputs/principal-log.md` 상단 기준 참조. 요약: 일회성 정오답이 아니라 **접근·설명 방식·우선순위·외부 입력(학원/시험)·3세션+ 반복 약점** 등 시스템 설계를 바꿔야 하는 신호.

## 실행 루틴

1. **읽기**:
   - `outputs/principal-log.md` (미검토 대기열 + 과거 검토 로그)
   - `student/profile.md`
   - `.claude/agents/{과목}-tutor.md` (해당 과목 에이전트 정의)
   - `outputs/curriculum/{과목}.md`
   - `data/academy_research.md`
   - `PROGRESS.md` (설계 결정 D-시리즈 + **마지막 D번호**)
   - `outputs/progress.md` (최근 세션·오답·누적 복습 트래커)
2. **신호 수집**:
   - 인수로 들어온 피드백 + 대기열 미검토 항목을 합쳐 과목별로 묶는다.
   - 과목 판별(수학/국어/영어/enrichment). 모호하면 한 번만 확인.
3. **증류 (핵심)** — 일회성 수정이 아니라 **1~3개 지속 원칙**으로. 각 원칙을 다음 4줄로 정리:
   - **관찰**: 무엇이 보였나 (구체적 사례)
   - **원칙**: 앞으로 시스템이 따를 일반 규칙 (한 단계 위 층위 — "이 약점을 강화하는 것이 결국 무엇을 돕는가"까지)
   - **근거**: 왜 일반화 가능한가 (교육학적 이유)
   - **적용 범위**: 어느 과목/단원/트랙/세션 단계에 적용
   - ⚠️ 절제: 한 번에 원칙 1~3개. 과하게 만들면 churn. 기존 에이전트 원칙과 충돌하면 충돌을 명시하고 갱신.
4. **일괄 자동 반영** (네 곳 모두 — 자동 적용 후 요약 보고 모드):
   - **(a) 과목 에이전트 정의** `.claude/agents/{과목}-tutor.md` → "## 원장 반영 원칙 (교육학 메타 레이어)" 섹션에 `- [YYYY-MM-DD] 원칙: …` 형식으로 추가/갱신. 에이전트가 매 자료 생성 시 의식하도록 본문 상단부에 둔다.
   - **(b) 커리큘럼** `outputs/curriculum/{과목}.md` → 단원 시퀀스·강조점·접근 방식 조정. 변경은 파일 하단 "조정 기록" 표에 일자·변경·이유 추가. 시퀀스 대수술이 필요하면 `curriculum-planner` subagent에 위임.
   - **(c) 학생 프로파일** `student/profile.md` → 원칙이 수준·접근·우선순위 변경을 함의하면 갱신. (단순 세션 진도·오답은 `/done` 담당이므로 중복 기록 최소화 — 여기선 "접근 원칙"만.)
   - **(d) PROGRESS.md** → 섹션 2에 새 결정 행 추가. **번호는 마지막 D번호 + 1** (현재 마지막 = D29부터 시작하면 +1). 섹션 4에 완료 체크 한 줄.
5. **대기열 갱신** `outputs/principal-log.md`:
   - 처리한 미검토 항목을 대기열 표에서 제거.
   - "✅ 검토 완료 로그" 맨 위에 이번 실행 블록 추가 (도출 원칙 + 반영 대상 4곳 + 연결 D번호).
6. **요약 보고** (자동 적용 후):
   ```
   원장 검토 완료 ([과목]). 도출 원칙 N개를 4곳에 반영했습니다.
   | 원칙 | 에이전트 | 커리큘럼 | 프로파일 | 결정로그 |
   원치 않는 변경이 있으면 말씀해 주세요 — 해당 부분만 되돌리거나 다시 조정합니다.
   ```

## 호출 시 주의
- **`/done`과 역할 분리**: `/done`=세션 결과 기록(매 세션, 빠름). `/principal`=원칙 전파(가끔·의도적, 영향 큼). 둘을 섞지 않는다.
- **자동 적용 + 명확한 요약** (부모 선택): 바로 반영하되 **무엇을→어디에 바꿨는지** 표로 분명히 보고. 부모가 보고 판단해 재요청 가능하게.
- **영향 범위 인지**: 에이전트 정의·커리큘럼은 시스템의 "뇌"다. 원칙은 1~3개로 절제하고, 기존 결정(D-시리즈)·각 에이전트의 금지 규칙(전문용어 금지·표절 금지·마인드 코칭 금지 등)과 충돌하지 않게.
- **PROGRESS.md 결정 규칙**: 기존 결정은 취소선만, 삭제 X. 새 번호는 마지막 D+1.
- **선제 제안**: 세션 시작 시 `outputs/principal-log.md` 미검토 대기열이 선제 제안 규칙(2건+ / 2주+ / 외부 자료 1건)에 해당하면, 작업 전에 부모에게 `/principal` 실행을 먼저 제안한다.
- **과목 공통 원칙**: 두 과목 이상에 걸치는 원칙(예: "성공 경험과 도전을 한 세션에 공존")은 각 과목 에이전트에 동일 취지로 반영하고 PROGRESS 결정 1개로 묶는다.
